# BL-AGENT-001：项目级 Agent 套件与飞书智能入口

## 背景

dual-tmux 当前的飞书入口以确定性 `/dt` 命令解析和转发为主，适合查询、恢复、发送等明确操作，但不能依据项目自身的约定理解自然语言目标、规划任务、选择工具并持续管理执行过程。

后续应允许每个受管项目声明自己的 Agent 配置与套件，并让飞书机器人连接到该 Agent，而不只是机械地透传命令。

## 目标目录

项目根目录下增加约定目录：

```text
agent/
├── AGENTS.md                 # 项目 Agent 的职责、边界、流程和长期约定
├── skills/                   # 项目专用技能或技能引用
├── tools/                    # 可调用工具及参数/权限声明
├── prompts/                  # 可版本化的任务模板
├── policies/                 # 安全、审批、写操作和外部动作策略
├── workflows/                # 常用工作流与状态机
└── tests/                    # Agent 行为、权限与回归用例
```

最终结构可在设计阶段调整，但 `agent/AGENTS.md` 是稳定入口；运行时密钥、会话、队列和用户数据不得写入或提交到该目录。

## 产品行为

### 飞书入口

- 同一个 dual-tmux 飞书机器人既支持确定性 `/dt` 控制命令，也支持自然语言 Agent 请求。
- `/dt` 命令继续由 ControlService 的规则代码执行，不依赖大模型，作为诊断、恢复和紧急控制底座。
- 非命令消息先完成用户、项目和目标 Client 的授权路由，再加载目标项目的 `agent/AGENTS.md` 与允许的套件，由 Agent 理解、规划和执行。
- 飞书侧展示任务计划、当前阶段、等待审批、执行进展、最终结果与失败原因，而不展示原始内部 JSON 或模型内部推理。
- 长任务必须使用 durable task/turn 状态，不能依赖某一台机器的常驻内存或单次 WebSocket 生命周期。

### 项目与多设备路由

- 每条 Agent 会话必须绑定 `tenant + user + project + agent profile`，禁止不同用户或项目间混用上下文。
- 一个用户有多台 Client 时，按照项目/隧道 owner 路由到真正持有工作区和会话的 Client；目标不唯一时先让用户选择，不静默猜测。
- Client 离线时任务进入可见的 queued 状态；恢复后仅执行仍在 TTL 内且权限仍有效的任务。
- 更换 Client、Hub 或飞书 WS owner 不得导致 Agent 会话、任务状态或审批记录丢失。

## 安全与治理不变量

- Agent 只能调用清单中显式允许的工具；默认最小权限。
- 读操作、可逆本地写操作、外部写操作和破坏性操作分级；需要审批的动作必须在飞书中明确确认。
- 指令来源、Agent 决策、工具调用、审批人与结果均产生可审计事件，但不得记录密钥或模型隐私数据。
- `AGENTS.md` 和套件属于项目版本化配置；运行时发现的远端内容不得未经信任校验提升权限。
- 防提示注入、目录越界、跨租户访问、重复事件执行和过期命令执行必须纳入威胁模型和测试。
- Agent 失败不能影响 `/dt health`、`/dt recover` 等确定性救援路径。

## 需要设计的接口

- Agent manifest：名称、版本、支持能力、入口文件、所需工具和最小权限。
- 项目发现与绑定：本地路径、SSH/Docker 工作点、tunnel owner 和项目稳定 ID 的映射。
- Feishu conversation → Agent session → durable task/turn 的映射与恢复协议。
- Agent runtime adapter：至少兼容 OpenCode、Codex、Claude，并记录客户端名称与版本。
- 工具调用、审批、取消、超时、重试、幂等和结果卡片协议。
- 项目套件升级与兼容策略，包含 schema/version migration 和安全回滚。

## 验收标准

- 一个含 `agent/AGENTS.md` 的示例项目可以从飞书接收自然语言目标，生成可见计划并完成一个受控任务。
- 同一飞书机器人可在至少两个项目间显式切换，Agent 上下文、文件权限和任务记录互不串扰。
- `/dt ls` 等原有确定性命令行为不变；自然语言失败后仍可用 `/dt health` 诊断。
- Agent 可跨 WS owner 切换、Client 短暂离线和进程重启恢复同一 durable task，且不会重复执行已完成工具调用。
- OpenCode、Codex、Claude 至少各完成一条真实 Agent E2E，并记录客户端版本。
- 未授权工具、目录越界、跨租户访问、重复飞书事件、过期任务和危险操作未审批均被拒绝并留下审计记录。
- 飞书回复采用 Markdown/卡片呈现计划、进度和结果，不直接返回内部 JSON。

## 依赖与建议排期

本项依赖公司列装基础设施先完成：多租户自动供给、按 tunnel owner 的多设备路由、命令 TTL/生命周期、durable task、中心可观测性和三客户端兼容矩阵。

建议先在 API/基础设施版本完成 manifest、session/task 协议与安全模型，再在后续 Web/列装版本交付项目管理 UI、飞书交互、审批和示例套件。当前状态为 `BACKLOG`，尚未进入具体版本承诺。

## 非目标

- 不用大模型替代所有 `/dt` 确定性命令。
- 不默认授予 Agent shell、Git push、发布或外部消息发送权限。
- 不在第一阶段建设通用 Agent 市场；先完成项目内可版本化、可审计、可恢复的最小闭环。
