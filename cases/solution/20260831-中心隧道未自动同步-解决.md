# 中心隧道未自动同步 — 解决方案

## 解决步骤

1. 先以 `dt pull` 将 tom7r 上 6 条中心记录恢复到当前 Client；不删除本地数据。
2. 新增 `hub.sync()`：下载中心快照，将本地与中心隧道取并集。
3. 同名隧道以 JSON `updated_at` 为逻辑时钟；缺失/非法时间回退文件 mtime。
4. 同一时间戳内容不同时，以内容摘要作确定性 tie-break，保证多个 Client 收敛。
5. `run_*.cmd` 跟随胜出隧道；孤立 entry 按 mtime 合并。
6. 上传合并快照时使用 rsync `--update`，降低并发同步覆盖中心新文件的风险。
7. `dt tick` 从自动 push 改为自动 merge-sync；显式 `dt push` / `dt pull` 语义保持不变。

## 不变量

- 不同步删除：一个 Client 的局部缺项不能删除中心记录。
- 不同步 `config.toml`、`ops/`、`events.jsonl`。
- Client 身份仍由本机配置决定，中心 JSON 中的来源字段不改写。
- 锁和 activity 继续使用原有独立路径与逻辑。

## 验证

- 自动化测试覆盖远端新增、本地较新、远端较新、entry 跟随、entry 缺失和同秒冲突。
- 全量 pytest：53 项通过。
- Python compileall 通过；sdist 与 wheel 构建通过。
- 使用当前配置对 tom7r 执行真实 `hub.sync()` 冒烟通过。
- 本地与 tom7r 均为同一组 6 条隧道，逐文件 SHA-256 一致。
